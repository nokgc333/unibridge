# ADR-0005: 自動修正ではなく検証+提示に留める設計

## Status
Accepted (2026-09-07)

## Context
座標系（upAxis）・スケール単位（metersPerUnit）の不整合を検出した際、UniBridgeが検出と同時に自動で変換・修正まで行うかどうかを検討した。自動修正はユーザー価値が高い一方、誤った方向への変換（例: 既に正しい座標系のシーンを誤って再変換してしまう）や、意図しないジオメトリの改変を引き起こすリスクを伴う（要件定義書§12.2の信頼境界、Tampering観点の脅威モデルとも関連）。

この判断は、姉妹プロジェクトScene DoctorのADR-0003（自動修正ではなくレポート＋提示に留める設計）、およびPipeInitの`--apply`フラグ既定offという設計判断と同じ思想に基づく。

## Decision
v1のスコープは、座標系・スケール単位・命名規則の不整合の**検出とレポート**に限定する。実際の変換（`apply_up_axis_conversion()` / `apply_scale_conversion()`）は、CLIでの`--apply`相当の明示フラグ指定、またはWeb GUIでの明示的な確認操作を必須とし、既定では一切のファイル書き換えを行わない。

## Consequences

良い: 誤操作によるシーン破壊・意図しない変換を防止できる（fail-safeな既定動作、Scene Doctor ADR-0003・PipeInitの`--apply`既定offと同一の設計思想を5プロジェクトにわたって一貫させている）。
悪い: 大量の不整合が検出された場合、1件ずつ変換を確認・適用するのが煩雑になりうる（将来のバッチ承認フローは拡張候補とする）。

## Alternatives Considered
- **検出と同時に即座に変換を自動実行する方式**: ユーザーの意図しない変更を招くリスクが高く、「デフォルトで安全」という設計原則（PipeInit・Scene Doctorと共通の判断軸）を優先し却下した。

# ADR-0009: 終了コードは「不整合」と「実行できなかった」を分ける

- 状態: 採用
- 日付: 2026-10-27

## 背景

CI やパイプラインのスクリプトは、終了コードで分岐する。「シーンに問題があった」と「ツールが動かなかった」を同じ値にすると、前者は差し戻し、後者は再実行、という別々の対応ができない。

## 決定

| コード | 意味 |
| ---: | --- |
| 0 | 検査に成功し、不整合なし |
| 1 | 検査に成功し、不整合あり |
| 10 | ファイルが無い・開けない(壊れた USD を含む) |
| 11 | 引数が不正 |
| 12 | 対象のノードが不正 |
| 13 | ルールファイルを読めない |
| 14 | 出力先に書けない |

`1` は「ツールは正しく動いた」ことを表し、`10` 以上は「動かせなかった」ことを表す。定義は `commands/exit_codes.py` の 1 か所にあり、`cli.py` が再公開する。

## 理由

- 壊れた USD で Python の例外(終了コード 1 とスタックトレース)が出ると、「不整合あり」と区別できない。例外は握りつぶさず、読めない理由を 1 行で標準エラーに出して、10 で終わる
- 2〜9 を空けているのは、`argparse` の引数エラー(2)など、標準の用途と衝突させないため

## 結果

- 検査系のコマンドは、スクリプトから `if [ $? -eq 1 ]` のように、結果の種類で分岐できる
- 新しい失敗の種類を足すときは、15 以降に割り当て、この表と `docs/仕様書.md` §5.7 を更新する
